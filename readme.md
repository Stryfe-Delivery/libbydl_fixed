# LibbyDL
a "simple" ebook downloader, bringing limited functionality to older unmaintained projects

ACSM downloading logic from: https://github.com/Leseratte10/acsm-calibre-plugin
DRM removal logic from: https://github.com/noDRM/DeDRM_tools
Original merger idea from: https://github.com/notmarek/libbydl

# ACSM → EPUB de-DRM Server

A single-file Flask app that accepts an `.acsm` file and produces a de-DRMed `.epub`. No Libby token, no pairing, no browser extension. The ACSM file is self-contained — it holds the Adobe operator URL and license token, so the server only needs a locally provisioned ADE key.

---

## File & folder structure

```
LibbyBookDL/
├── app.py                    # the server (this is the only file you need to edit for features)
├── requirements.txt          # pip dependencies
├── cert.pem                  # HTTPS certificate (generated below)
├── key.pem                   # HTTPS private key (generated below)
│
├── books/                    # output — de-DRMed EPUBs land here
├── keys/                     # ADE crypto material (generated by provision-ade-account)
│   ├── device.key
│   ├── device.xml
│   ├── activation.xml
│   └── decryption.der
│
└── LibbyDL/                  # de-DRM library (vendored)
    └── DeDRM/
        ├── __init__.py
        ├── dedrm_acsm.py     # dedrm() entry point
        ├── ineptepub.py      # EPUB decryption
        ├── libadobe.py       # ADE primitives
        ├── libadobeAccount.py
        └── libadobeFulfill.py
```

Directories `books/` and `keys/` are created automatically. `cert.pem`/`key.pem` you generate once. `LibbyDL/` comes from the de-DRM project.

## Setup

### 1. Create a virtualenv and install dependencies

```bash
cd ~/Documents/LibbyBookDL
python3 -m venv .venv
source .venv/bin/activate

pip install flask flask-cors loguru requests lxml cryptography pyopenssl
```

If you keep a `requirements.txt`, it should contain:

```
flask
flask-cors
loguru
requests
lxml
cryptography
pyopenssl
```

### 2. Vendor the de-DRM library

Either copy `LibbyDL/` into the project root (as shown in the tree above), or install it into the venv:

```bash
pip install -e /path/to/LibbyDL
```

### 3. Provision the ADE account (once)

```bash
python app.py provision-ade-account
```

This creates `keys/` with your device key and the decryption key. Run it once per machine — the keys persist.

If it succeeds, `keys/decryption.der` exists and the web UI's status banner will stay hidden.

### 4. Generate a self-signed HTTPS certificate (once)

The de-DRM server uses HTTPS because browsers block HTTP uploads from `file://`-adjacent contexts and Firefox's MV3 upgrades insecure requests. A self-signed cert works fine on a LAN.

```bash
cd ~/Documents/LibbyBookDL
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout key.pem \
  -out cert.pem \
  -subj "/CN= [insert pc name here]" \
  -addext "subjectAltName=DNS:webdev,IP:192.168.1.100"
```

Replace `insert here` with your server's hostname and `192.168.1.100` with its LAN IP. Include both so either form resolves.

Verify:

```bash
ls -l cert.pem key.pem
openssl x509 -in cert.pem -noout -text | grep -A1 "Subject Alternative Name"
```

## Run

```bash
python app.py serve --cert ./cert.pem --key ./key.pem
```

You'll see:

```
INFO | Open https://0.0.0.0:5000
 * Running on https://0.0.0.0:5000
```

No service file needed — run it in a terminal, a `tmux`/`screen` session, or whatever fits your workflow. If you want it to auto-start later, wrap it in a systemd unit (not covered here).

### Accept the certificate once, per browser

From the machine you'll browse from, visit:

```
https://[server_name]:5000/
```

Firefox/Chrome will show "Warning: Potential Security Risk Ahead". Click **Advanced → Accept the Risk and Continue**. This stores the exception for that host+port and everything works from then on.

---

## Use

1. Open `https://[server_name]:5000/` in your browser.
2. Go to `libbyapp.com` (or wherever the ACSM originates), click **Download EPUB**, save the `.acsm` file.
3. Back on the server UI → **Upload** tab → **Choose file** → pick the `.acsm` → **Upload & de-DRM**.
4. Switch to the **Files** tab. The decrypted `.epub` is listed and clickable for download.

The EPUB is also written to `books/` on disk.

## CLI reference

| Command | What it does |
|---|---|
| `python app.py` | Same as `serve` with defaults (`0.0.0.0:5000`, no TLS) |
| `python app.py serve --cert ./cert.pem --key ./key.pem` | Run the web UI over HTTPS |
| `python app.py dedrm <url-or-path>` | De-DRM a single ACSM from the shell (skips the UI) |
| `python app.py provision-ade-account` | One-time ADE key setup |

`serve` accepts `--host` and `--port` if you need to change the bind address.

## HTTP API

| Method | Path | Body | Response |
|---|---|---|---|
| `GET` | `/` | — | Web UI |
| `GET` | `/api/status` | — | `{"ade_provisioned": true/false}` |
| `POST` | `/api/dedrm` | `{"content_b64": "<b64 ACSM>"}` or `{"source": "<url-or-path>"}` | `{"ok": true}` or `{"error": "..."}` |
| `GET` | `/api/books` | — | `{"files": ["Author - Title.epub", ...]}` |
| `GET` | `/books/<name>` | — | The EPUB file |

The `source` mode is useful for scripting — you can hand it an Adobe `fulfill.contentreserve.com/...acsm?Token=...` URL directly and it will fetch and decrypt in one call:

```bash
python app.py dedrm "https://fulfill.contentreserve.com/Book_12345.acsm?RetailerID=...&Token=...&Signature=..."
```

## Troubleshooting

**`Error: No such option '--cert'`** — your `app.py` is out of date. The current `serve` command defines `--cert` and `--key`.

**`FileNotFoundError: ./cert.pem`** — run from the directory containing the cert, or use absolute paths.

**`SSL_ERROR_BAD_CERT_DOMAIN`** in the browser — the cert's SAN doesn't match the URL you're using. Regenerate with the right `subjectAltName` for whichever hostname/IP you're visiting.

**`ADEDecryptionKeyNotFound` / `decryption.der` missing** — run `python app.py provision-ade-account` once.

**Upload succeeds but no EPUB appears** — check the server terminal. `dedrm()` logs the Adobe fulfillment and download steps. A 403 from Adobe's fulfillment server means the ADE account needs re-provisioning, or the ACSM has expired (`Expires=` param in the URL is a Unix timestamp).

**Firefox blocks the upload** — you're probably on HTTP. Use HTTPS with the cert; the browser will accept a self-signed cert on a LAN after the one-time warning.

## Notes

- No Libby token, no pairing, no config file. Delete `config.json` if you have one lying around from the old build.
- No more browser extension. The upload is a plain HTTPS POST from the page itself.
- `books/` is world-readable on the LAN if you expose the server. If that matters, bind to `127.0.0.1` and reverse-proxy with auth, or run it behind a VPN.
- The server is single-user. Multiple concurrent uploads work but share the same `books/` folder and ADE key.
